## 2. 模块与需求映射

| 模块 | 主要职责 | 实验一需求 |
| --- | --- | --- |
| 账号与权限 | 注册登录、改密、工作人员账号、权限校验 | REQ-001～002、REQ-027、REQ-033 |
| 活动与治理 | 类别、活动草稿与审核、发布、取消、举报、下架 | REQ-003～008、REQ-019～021 |
| 报名、订单与候补 | 查询、占位、模拟支付退款、超时、自动递补 | REQ-009～015、REQ-028～029、REQ-031～032 |
| 票务与检票 | 电子票、票码核验、签到、缺席 | REQ-016～018 |
| 统计、导出与审计 | 名单、统计、CSV、操作日志、归档 | REQ-022～026、REQ-030、REQ-034 |

支撑组件：关系数据库、定时到期任务、站内通知。对票与订单的状态更新统一在事务中完成；真实支付、外部短信、选座均不进入实现范围。

## 5. 顺序与核查

1. 固定模块、业务对象和边界，保存 AI 初稿。
2. 绘制 PlantUML 源码并渲染 PNG；核对角色权限、1:1 场次票种、状态转换和并发约束。
3. 用可编辑矢量界面源设计 UI 并导出 PNG；逐页对应模块与需求编号。
4. 编写报告，记录每次 AI 辅助的场景、原始结果、优缺点与修改后的结果；不冒称尚未发生的人工审查。
5. 渲染并目测报告与图，核对 ZIP 文件树，使用 Git 分别记录 AI 草稿和后续审查修改。
